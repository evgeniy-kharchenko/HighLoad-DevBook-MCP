# Спецификация GitLab Project Registry

Нужно реализовать небольшой сервис GitLab Project Registry на Python.

## Назначение сервиса

Сервис хранит информацию о GitLab проектах в базе данных и позволяет синхронизировать эти данные с GitLab через HTTP API.

## Сущность Project

У проекта должны храниться следующие данные:

- `id`
- `gitlab_project_id`
- `name`
- `path_with_namespace`
- `web_url`
- `default_branch`
- `created_at`
- `updated_at`

## API

| Метод и путь               | Операция                                 |
| -------------------------- | ---------------------------------------- |
| `POST /projects`           | Создает новую запись о GitLab проекте.   |
| `GET /projects/{id}`       | Возвращает проект по его идентификатору. |
| `GET /projects`            | Возвращает список сохраненных проектов.  |
| `PATCH /projects/{id}`     | Позволяет изменить данные проекта.       |
| `DELETE /projects/{id}`    | Удаляет проект.                          |
| `POST /projects/{id}/sync` | Синхронизирует проект с GitLab.          |

Для синхронизации сервис должен получить актуальную информацию о проекте из GitLab по значению `gitlab_project_id` и обновить `name`, `path_with_namespace`, `web_url` и `default_branch`.

## Интеграция с GitLab

Для получения данных использовать HTTP API GitLab. Адрес GitLab и токен доступа должны передаваться через конфигурацию приложения.

## Хранение данных

Данные проектов должны храниться в базе данных.

## Тестирование

Необходимо добавить тесты для основных сценариев работы сервиса.

## Ограничения

Авторизация пользователей не требуется. Пользовательский интерфейс не требуется.

Конкретные библиотеки, структуру проекта, способ работы с HTTP, базой данных, обработкой ошибок, конфигурацией, логированием и тестированием нужно выбрать самостоятельно.

Если в проекте доступны инженерные стандарты или гайдлайны, их необходимо использовать при принятии технических решений.
