# GitLab Project Registry

Сервис хранит реестр проектов в SQLite и синхронизирует их метаданные через GitLab REST API. Требуется Python 3.11 или новее. Сторонних зависимостей нет.

## Окружение и зависимости

`pyproject.toml` задаёт поддерживаемую версию Python и список зависимостей, а `uv.lock` фиксирует результат разрешения. Сейчас приложение и тесты используют стандартную библиотеку, поэтому список сторонних пакетов пуст.

```sh
uv sync --locked
uv run --locked python registry.py
uv run --locked python -W error -m unittest -v
```

Добавляйте зависимости приложения через `uv add <package>`, а зависимости для разработки и тестирования — через `uv add --dev <package>`. Сохраняйте изменения `pyproject.toml` и `uv.lock` вместе. В CI используйте `uv sync --locked`, чтобы устаревший lock-файл приводил к ошибке.

## Запуск

Из этой директории выполните `python3 registry.py`. По умолчанию API доступен по адресу `http://127.0.0.1:8000`.

| Переменная      | По умолчанию         | Назначение                                                       |
| --------------- | -------------------- | ---------------------------------------------------------------- |
| `DATABASE_PATH` | `projects.sqlite3`   | Путь к файлу SQLite                                              |
| `GITLAB_URL`    | `https://gitlab.com` | Базовый URL GitLab, включая префикс при размещении в подкаталоге |
| `GITLAB_TOKEN`  | Пусто                | Токен с доступом на чтение проекта через API GitLab              |
| `HOST`          | `127.0.0.1`          | Адрес прослушивания                                              |
| `PORT`          | `8000`               | Порт прослушивания                                               |

Передайте реальный токен через окружение. Встроенный WSGI-сервер предназначен для локального запуска. API работает без авторизации.

## API

| Запрос                     | Успешный ответ                                    |
| -------------------------- | ------------------------------------------------- |
| `POST /projects`           | `201`, проект и заголовок `Location`              |
| `GET /projects/{id}`       | `200`, проект                                     |
| `GET /projects`            | `200`, массив проектов в порядке возрастания `id` |
| `PATCH /projects/{id}`     | `200`, проект после изменения переданных полей    |
| `DELETE /projects/{id}`    | `204`, без тела                                   |
| `POST /projects/{id}/sync` | `200`, проект с метаданными GitLab                |

Для создания передайте JSON с положительным целым `gitlab_project_id` и непустыми строками `name`, `path_with_namespace`, `web_url`. Поле `default_branch` принимает непустую строку или `null` и может отсутствовать. Сервер назначает локальный `id` и выставляет `created_at` и `updated_at` в UTC. Поля из тела создания можно менять через PATCH. Повторяющийся `gitlab_project_id` возвращает `409`.

```sh
curl -i http://127.0.0.1:8000/projects \
  -H 'Content-Type: application/json' \
  -d '{"gitlab_project_id":123,"name":"Registry","path_with_namespace":"team/registry","web_url":"https://gitlab.example/team/registry","default_branch":"main"}'
curl -i -X POST http://127.0.0.1:8000/projects/1/sync
```

Синхронизация выполняет `GET /api/v4/projects/{gitlab_project_id}` с заголовком `PRIVATE-TOKEN`, затем сохраняет четыре поля метаданных одной транзакцией. При ошибке GitLab или некорректных метаданных API возвращает `502`, а при отсутствующем токене — `503`. Ответы об ошибках содержат JSON с полем `error`.

## Проверки

```sh
python3 -m unittest -v
```

Тесты используют временные файлы SQLite и подставляют ответы на границе HTTP-клиента. Токен и доступ к GitLab для тестов не нужны.
