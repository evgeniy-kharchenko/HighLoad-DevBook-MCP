# Отчёт о выполнении

**Модель** — GPT-6.2 Sol (`gpt-6.2-sol`, по событию `turn_context` в журнале Codex). **Режим** — без DevBook MCP. Базовый коммит — `2a91a86`. Проверки выполнены в `without-devbook/` на Python 3.15.2.

## Реализация и проверки

Реализованы шесть операций API, файловое хранение в SQLite и синхронизация с GitLab REST API v4. Синхронизация загружает данные до записи в БД и сохраняет четыре поля метаданных одной транзакцией. При изменении привязки проекта во время HTTP-запроса условное обновление защищает новую привязку от записи данных прежнего проекта. Конфигурация GitLab и SQLite передаётся через окружение. Схема создаётся при запуске.

| Проверка                                                 | Результат                                                                                                                                            |
| -------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `python3 -W error -m unittest -v`                        | 6 из 6. CRUD, повторное открытие БД, валидация, конфликт идентификаторов, успешная и ошибочная синхронизация, смена привязки во время синхронизации. |

На первом прогоне тестов валидатор WSGI предупредил об отсутствующем `QUERY_STRING` в тестовом окружении. Поле добавлено, повторный прогон с предупреждениями как ошибками прошёл. Оболочка выводила предупреждение `pyenv` о записи в каталог shims, Python и проверки запускались.

Ограничения реализации — список возвращается целиком, встроенный WSGI-сервер предназначен для локального запуска. Успешная синхронизация и сбои GitLab проверены с подставными ответами HTTP-клиента. Реальный GitLab в проверках не участвовал.

## Экономика решения

- **Разработка.** 84,2% входных токенов пришлись на чтение кэша. При тех же объёмах входа и выхода и оплате всего входа по обычной ставке оценка составила бы 0,743904 USD. Кэш уменьшил расчётную стоимость примерно на 0,53 USD, или на 71%. В оценку разработки входят только токены исходного прогона. Время ручной проверки и сопровождения не измерялось.
- **Эксплуатация.** Сервис работает на Python и SQLite. Запуск требует процесса приложения и диска под файл БД. API сервиса не использует модель и не расходует токены OpenAI. При развёртывании основными статьями расходов будут хостинг, хранилище, резервные копии и сопровождение. Месячную сумму можно посчитать после выбора хоста и объёма хранения.
- **Нагрузка.** CRUD обслуживается локально. Каждый вызов синхронизации существующего проекта при настроенном токене отправляет один запрос в GitLab. Например, ежедневная синхронизация 100 проектов в течение 30 дней даёт около 3 000 запросов к GitLab. Для оценки масштабирования нужны частота синхронизации, размер списка проектов и доля параллельных записей. Крупные списки увеличивают размер ответа, а параллельные записи конкурируют за блокировку SQLite.

## Чего хватило и чего не хватало

- `PROMPT.md` и `SPEC.md` задали порядок работы, поля, шесть маршрутов и состав метаданных для синхронизации. `README.md`, `CONTRIBUTING.md`, `DEMO.md` и `SECURITY.md` помогли зафиксировать условия прогона и базовый коммит, отделить артефакты двух прогонов и оставить секреты в окружении.
- Стандартной библиотеки Python, временных файлов SQLite, валидатора WSGI и подставных HTTP-ответов хватило для проверок контракта, персистентности и обработки сбоев без установки зависимостей.
- Репозиторий не задаёт инженерный стандарт для Python, базы данных и HTTP-ошибок. Использованы стандартная библиотека, параметризованные SQL-запросы, транзакции и коды HTTP. Внутренний гайдлайн позволил бы сверить эти решения с требованиями команды.
- В спецификации нет примеров JSON и правил для дубликатов, пустых репозиториев и PATCH. Приняты уникальность GitLab ID, nullable `default_branch`, частичное обновление с сохранением пропущенных полей и служебные UTC-метки, которыми управляет сервер. Эти решения определяют совместимость клиентов. Согласованная OpenAPI-схема закрепила бы контракт.
- URL тестового GitLab, тестовый проект и учётные данные не предоставлены. Подставные ответы проверяют HTTP-запрос, обработку ответа и запись в БД. Тестовый инстанс и токен чтения позволили бы проверить интеграцию с реальным GitLab.
- Журнал Codex дал фактические счётчики токенов, а публичный тариф API позволил оценить их стоимость. Для сверки фактического списания нужны данные биллинга аккаунта.

## Управление зависимостями после исходного прогона

Добавлены `pyproject.toml` и `uv.lock`. Минимальная версия Python зафиксирована как 3.11. Приложение и тесты используют стандартную библиотеку, поэтому сторонних пакетов в lock-файле нет. На uv 0.13.9 и Python 3.15.2 выполнены офлайн-синхронизация окружения с `--locked` и повторный прогон тестов. Все 6 тестов прошли. Токены этого изменения находятся за пределами исходного прогона, измеренного выше.
