# Проведение демо

## Подготовка

Для каждого прогона создайте отдельную пустую рабочую папку вне этого репозитория. Откройте каждую папку как самостоятельный проект в новой сессии агента. Так агент во время генерации не увидит результат другого прогона в соседней директории.

Зафиксируйте модель и её настройки, версию агента, доступные инструменты и лимит времени. Подготовьте одинаковые условия работы с GitLab API для обоих прогонов.

Возьмите полный текст [PROMPT.md](PROMPT.md) и добавьте после него полный текст [SPEC.md](SPEC.md). Отправьте получившееся сообщение без изменений в обе сессии.

## Запуск и сохранение результатов

| Прогон | Настройка сессии | Куда сохранить результат |
| --- | --- | --- |
| Без DevBook | Отключите DevBook MCP до отправки сообщения. | [`without-devbook/`](without-devbook/) |
| С DevBook | Подключите DevBook MCP до отправки сообщения и зафиксируйте версию доступных стандартов. | [`with-devbook/`](with-devbook/) |

Сохраните одинаковые настройки всех остальных инструментов. После завершения обоих прогонов перенесите исходный код, тесты и файлы проекта в соответствующие директории. При повторном прогоне сохраните предыдущий результат в Git перед заменой файлов. Секреты и локальные окружения оставьте в рабочих папках.

Зафиксируйте результаты проверок, ручные вмешательства, повторные попытки и стандарты, к которым обратился агент.

## Сравнение

Запустите одинаковые проверки в обеих копиях. Оцените полноту API, хранение данных, синхронизацию с GitLab, обработку ошибок, настройку сервиса, тесты и соответствие выбранным инженерным стандартам. Для каждого наблюдения приведите пример из кода, результат проверки или ссылку на конкретный стандарт.

Одна пара прогонов иллюстрирует возможный эффект инженерного контекста. Для оценки воспроизводимости повторите эксперимент с теми же условиями.
